Threat Model

STRIDE-informed analysis · MITRE ATT&CK mapping · Architectural boundaries

🎯 Adversary Assumptions

  • External attacker with knowledge of common web injection techniques
  • Target application processes user input without server-side sanitization
  • Attacker may use automated scanners (SQLMap, XSStrike, Nikto)
  • Not assumed: network-level access, proxy bypass via direct TCP
  • Out of scope: authenticated insider threats, SSL stripping

🏗️ System Boundaries

  • In scope: HTTP/HTTPS traffic through the mitmproxy intercept layer
  • Intercepted: GET query params, POST form bodies, POST JSON payloads
  • Not intercepted: Direct TCP, WebSocket frames, binary protocols
  • Trust boundary: Between client browser and application server
  • Detection engines: Groq Llama 3.3 70B → Gemini 2.0 Flash → Rules

⚡ Performance Characteristics

  • Groq Llama 3.3 70B: ~100–300ms per field, 6,000 RPM free
  • Gemini 2.0 Flash: 800ms–3s per field, 15 RPM free (fallback)
  • Rule-based fallback: <1ms per field, always active
  • LRU Cache: 512 entries — repeated payloads served instantly
  • Rate limiter: 12 Groq calls/min with automatic fallback

🔐 Decision Policy (Strict Mode)

  • Block (403): Critical or High risk — request terminated, custom block page served
  • Sanitize: Medium risk — payload stripped, clean request forwarded
  • Allow: Low / Benign — forwarded unchanged
  • All decisions logged to SQLite with CVE + MITRE ATT&CK enrichment

🚧 Known Limitations & Roadmap

  • Encoding evasion: Base64, URL double-encoding bypasses may evade rules. Groq handles these better via semantic understanding.
  • Context blindness: Fields analysed individually — multi-field second-order attacks not detected.
  • Localhost proxy: macOS bypasses system proxy for localhost; requires --proxy-bypass-list="<-loopback>" Chrome flag.
  • Roadmap: Transparent proxy mode (pfctl), rate limiting, session-level anomaly detection, async AI pipeline for <10ms overhead.
